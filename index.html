Git y GitHub
desde la consola

Una guía completa para comenzar a controlar versiones de tus proyectos y colaborar sin perder tu trabajo.

Guarda tu progreso.
Comparte tu trabajo.

Git controla el historial de archivos en tu computadora. GitHub guarda ese historial en línea para respaldarlo, compartirlo y trabajar con otras personas.

Regla de oro

Antes de ejecutar un comando que modifique o publique cambios, usa git status. Nunca subas contraseñas, tokens, archivos .env ni información privada.

01

Prepara Git en tu equipo

Instala Git desde git-scm.com y abre PowerShell, Terminal o Git Bash. Configura tu nombre y un correo verificado en GitHub; aparecerán como autor de tus commits.

Configurar una vezgit config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@ejemplo.com"
git config --global --list

La última línea permite revisar la configuración guardada. Usa tu correo real, no el ejemplo.

02

Obtén o crea un proyecto

Si el proyecto ya existe en GitHub, clónalo. Si es nuevo, inicializa Git dentro de la carpeta y enlázalo después con un repositorio vacío de GitHub.

Proyecto existentegit clone https://github.com/usuario/proyecto.git
cd proyecto

clone descarga los archivos y su historial. cd entra a la carpeta descargada.

Proyecto nuevocd ruta/de/tu/proyecto
git init
git branch -M main

init activa el control de versiones. La última línea nombra la rama principal como main.

03

El ciclo diario de trabajo

Este es el orden que repetirás cada vez que edites un proyecto: actualizar, revisar, preparar, guardar y publicar.

1. Actualizargit pull origin main

Descarga y combina los cambios que ya están en GitHub. Hazlo antes de editar cuando trabajas con otras personas.

2. Revisargit status
git diff

status muestra qué archivos cambiaron. diff muestra las líneas modificadas que aún no has preparado.

3. Preparargit add nombre-del-archivo.html
git add .

El primer comando prepara un archivo específico; el segundo prepara todos los cambios. Revisa git status antes de usar el punto.

4. Guardargit commit -m "Agrega sección de aprendizaje"

Un commit es una fotografía con mensaje. Describe la acción en presente: “Corrige menú”, “Actualiza glosario” o “Agrega guía”.

5. Publicargit push origin main

Envía tus commits a GitHub. La primera vez puede abrirse una ventana para iniciar sesión y autorizar Git.

04

Conecta un proyecto nuevo con GitHub

Crea un repositorio vacío en GitHub, copia su dirección HTTPS y ejecuta estos comandos desde la carpeta de tu proyecto para guardar y publicar su primera versión.

Enlazar y publicar por primera vezgit remote add origin https://github.com/usuario/proyecto.git
git add .
git commit -m "Primer commit"
git push -u origin main

origin es el nombre habitual del repositorio remoto. La opción -u recuerda la conexión, por lo que después bastará con git push.

05

Trabaja con ramas sin afectar main

Una rama permite desarrollar una idea de forma aislada. Es útil para una función nueva, un experimento o una corrección antes de integrarla al proyecto principal.

Crear y cambiar de ramagit switch -c nueva-seccion
git status

La rama se crea y queda activa. Realiza tus cambios, usa git add y git commit como siempre.

Subir y volver a maingit push -u origin nueva-seccion
git switch main
git pull origin main

En GitHub podrás abrir un Pull Request para revisar e integrar la rama. Actualiza main antes de continuar.

06

Problemas comunes y cómo responder

Los mensajes de Git son información, no una señal para borrar archivos. Lee el mensaje, ejecuta git status y resuelve un paso a la vez.

“Nothing to commit”

No hay cambios preparados. Guarda el archivo, ejecuta git status y luego git add si corresponde.

Push rechazado

Hay cambios remotos que no tienes. Ejecuta git pull origin main, resuelve cualquier conflicto, crea un nuevo commit y vuelve a hacer git push.

Conflicto de merge

Dos personas modificaron la misma parte. Abre el archivo marcado, elige o combina el contenido, elimina las marcas <<<<<<<, guarda y ejecuta git add seguido de git commit.

Resumen del flujo

git pull → editar → git status → git add → git commit → git push. Repite este orden y tendrás un historial claro, respaldado y fácil de compartir.
